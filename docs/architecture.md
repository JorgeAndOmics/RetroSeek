# Architecture

RetroSeek is a Snakemake-orchestrated bioinformatics pipeline combining Python, R, and Bash to detect endogenous retroviral (ERV) integrations in eukaryotic genomes.

## Stack

- **Orchestrator**: Snakemake >= 8.
- **Python 3.11**: probe extraction, BLAST execution, object serialisation, validation, CLI.
- **R 4.3**: range analysis, segmentation, hotspot detection, pair detection, plotting.
- **External tools** (provided by the conda env):
  - BLAST+ (`tblastn`, `blastn`, `makeblastdb`).
  - GenomeTools (`gt suffixerator`, `gt ltrharvest`, `gt ltrdigest`, `gt gff3`).
  - NCBI Datasets CLI (`datasets`).
  - Pfam HMMs (downloaded on demand).
- **Reproducibility**: single conda/mamba env at [`data/config/environment.yml`](../data/config/environment.yml).

## Data flow

```
probe CSV --> probe_extractor (Entrez) --> probe_dict.pkl
                                              |
genome list --> genome_downloader (datasets) --> {genome}.fa
                       |
                       +-> blast_db_generator (makeblastdb)  -> per-genome BLAST DB
                       +-> ltr_index_generator (suffixerator)
                       |     +-> ltr_harvester                -> {genome}.gff3 + fa
                       |           +-> ltr_digester (Pfam)    -> {genome}.gff3 (annotated)
                       |
                       +-> full_genome_blaster (tblastn)      -> {genome}.pkl
                                                                  |
                             obj2dict <--- all {genome}.pkl ------+
                                   |
                                   +-> species_segmenter.R
                                   +-> ranges_analysis.R
                                             |
                                             +-> GFF3 tracks (original, candidate, valid [+valid _reduced])
                                             +-> overlap matrix (CSV)
                                             +-> plot dataframes (Parquet)
                                                   |
                                                   +-> plot2sort.R          (global plots)
                                                   +-> circle_plot_generator.R
                                                   +-> hotspot_detector.R
                                                   +-> pair_detector.R
```

## Rule overview

All rules follow `<name>_setup` (per-wildcard) + `<name>` (aggregate via `expand`). Groups:

**Acquisition** - `genome_downloader`, `pfam_hmm_downloader`.
**Indexing** - `blast_db_generator`, `ltr_index_generator`.
**LTR discovery** - `ltr_harvester`, `ltr_digester` (depends on both LTR_harvest outputs and the Pfam HMM download).
**BLAST search** - `probe_extractor`, `full_genome_blaster`, `blast_pkl2parquet`.
**Integration & segmentation** - `species_segmenter`, `ranges_analysis` (phase-modular: `workflow/scripts/ranges_analysis.R` is a thin orchestrator over sibling modules in `workflow/scripts/ranges/{io,granges_build,filtering,reductions,validation,stage_dataframe,plot_dataframe,exporters}.R, plus the shared workflow/scripts/range_aggregation_strategies.R`).
**Solo-LTR detection (native, ADR-017)** - `solo_bait_builder`, `solo_blaster`, `solo_finder`, `solo_annotator`, `solo_tree`, `solo_plot_generator`, `solo_plot_summary`, `solo_ltr_detector` (aggregate). Uses the LTR arms of ERV-bearing elements as `blastn` bait, then subtracts the hits that overlap an intact element (flanking arms) or sit within a proviral distance of an orphan locus (monoLTRs beside surviving coding sequence). What remains is a solo LTR. Writes `tracks/solo_ltr/`, `tables/solo_ltr/`, `trees/solo_ltr/`, and one multi-page PDF per genome under `plots/classification/solo_ltr/`. See [`docs/solo_ltr.md`](solo_ltr.md) for the mechanism and [ADR-017](adr/ADR-017-native-solo-ltr-detection.md) for the decision and its calibration.

**Taxonomic classification** - `taxonomy_reference` + `taxonomy_reference_trees` (build-once reference: taxon-comprehensive proteins via Entrez, NCBI taxonomy, curated `erv_class.tsv`, per-gene placement trees; `make reference` / `--build-reference`), then `taxonomy_classify` (per-locus taxon calls), `taxonomy_orphans` (recovered, proximity-clustered orphans tier), `taxonomy_plot_generator`, and `loss_analysis` (`--classify`). The classification is **rank-agnostic** (ADR-008): the axis of taxa a locus can resolve to is declared by `classification.reference_taxa` (any rank; defaults to the distinct probeset `Label` values). Reclassifies each valid LTR-element locus from its own marker sequence - POL/GAG by phylogenetic placement, weighted-LCA otherwise - into a calibrated `taxon_call` + `rank` (resolved to an axis taxon, or an honest backoff) with confidence, `confidence_tag` HC/LC vs `classification.confidence_min`, `n_blastx_hits`, method, mosaic, and ERV class. The per-locus loci table is the taxon-founded ERV assembly, carrying a discrete `structure_class` (full / partial / gene) and per-provirus `domain_tier` (domain_selected / domain_unlisted / non_domain) alongside the taxon call (ADR-009); legacy probe `virus`/`label` are kept as detection provenance (`probe_label_set`). Note the **valid tier is now the whole LTR-flanked set** - every LTR-overlapping hit is labelled (with `domain_tier` + a per-hit `domain_hit_class`) rather than filtered, so no LTR-flanked hit is discarded (ADR-009). A parallel **orphan tier** recovers non-LTR-associated hits - reduced BLAST hits overlapping no retrotransposon - by running the same classifier on them and keeping only those that earn a taxonomic call (the novel-retrovirus path; `source=orphan`). Orphans have no LTR element to group by, so their hits are clustered by **physical overlap** (co-location = same feature) into single non-overlapping loci - assembled by the same machinery, flagged `source=orphan` (proximity-*inferred* vs LTR-*confirmed*), and capped at the widest LTRdigest element per genome (clusters wider than any real provirus get an `oversized` flag, kept for filtering). Overlap-only means orphan loci are mostly single-gene (adjacent genes don't overlap) - a conservative dedup, not speculative multi-gene assembly (ADR-010). The LTR-flanked  U  orphan union is written as one fully non-overlapping authoritative `catalog.csv` (LTR-flanked-precedence resolves the cross-tier edge). `loss_analysis` then unions the ranges-analysis and blastx-stage counts into one per-stage attrition funnel and exports per-genome novel candidates (loci with `n_blastx_hits == 0`). Two further stages hang off the catalog (ADR-011): `taxonomy_tree_layout` writes flat tree coordinates - a cladogram of the observed axis taxa derived from the reference `taxonomy.tsv`, plus the user's pinned host-species Newick (`input.species_tree`) pruned to the study - using Bio.Phylo, so the R panels draw trees with `geom_segment` and **no R tree library**; and `taxonomy_segments` (`--segment`) splits the catalog by the taxon each locus rolls up to at `classification.segment_rank` (any rank; calls coarser than it become `unassigned_at_<rank>`). See [configuration.md `## classification`](configuration.md), [`docs/taxonomy_classification/`](taxonomy_classification/), [ADR-007](adr/ADR-007-taxonomic-classification.md), [ADR-008](adr/ADR-008-rank-agnostic-classification.md), and [ADR-011](adr/ADR-011-phylogeny-aware-plots-and-rank-segmentation.md).
**Downstream analyses** - `plot_generator` (phase-modular: `workflow/scripts/plot2sort.R` is a slim orchestrator over sibling modules in `workflow/scripts/plot2sort/{helpers,io,plots_distribution,plots_categorical,plots_sankey}.R`; writes the 22-page homology PDF, with opt-in long-tail collapse via `sankey_top_n` and waffle auto-scaling, including a detected-virus stacked bar per species), `stage_plot_generator` (the 18-page integration PDF: concordance/structure/funnel/multiplicity + pre-reduction overlap + LTR-interaction), `erv_like_plot_generator` (the 7-page *structural* PDF read from the taxon-founded taxonomy loci table: completeness, canonical order, gene combinations, length, main-gene count, taxonxgene composition, structure_class), `circle_plot_generator`, `hotspot_detector`, `pair_detector`. `--generate-global-plots` drives the ranges panel (`plot_generator` + `stage_plot_generator`) plus the structure panel (`erv_like_plot_generator`).

## Outputs

- `results/tracks/` - GFF3 per stage (`original`, `candidate`, `orphans`, `valid`, `flanking_ltr`, `ltrdigest`, `ltrharvest`, `solo_ltr`, `taxonomy`). `orphans/{genome}.gff3` is the orphan (non-LTR) hit set, carrying a synthetic `Parent=` from proximity clustering; `orphans/{genome}.classified.{gff3,bed}` is the recovered, taxonomically-called subset. Only `valid` carries a `_reduced` variant (merged overlapping ranges); `original`/`candidate` are unreduced. The composite ERV "assembly" is no longer a separate `erv_like` track - it is now the taxon-founded `taxonomy/{genome}.gff3` (one feature per LTR-element locus, labelled by `taxon_call`). `solo_ltr/{genome}.gff3` carries solo LTRs with taxonomy inherited from the element whose LTR arm caught them (see `docs/solo_ltr.md`).
- `results/trees/` - phylogenetic interchange formats (Newick, Nexus, jplace). A fourth output root beside `tracks/` on the same logic: `tracks/` holds what a **genome** browser opens, `trees/` holds what a **tree** viewer (iTOL, FigTree) opens. `placements/{genome}.{tier}.{gene}.jplace` + `.labelled.newick` are which branch of the retroviral phylogeny each locus attached to, with likelihood weights - the evidence behind every `taxon_call`; `placements/heat_trees/` holds the Newick/Nexus twins of the heat-tree SVGs; `cophylogeny/erv_composition.{tier}.{gene}.newick` is the ERV-composition tree of the host genomes, with gappa's per-cluster-node mass trees a level down in `cophylogeny/cluster_mass/`.
- `results/tables/<name>/` - user-facing **CSV** copy of every table group, each in its own subdirectory (no loose files): `ranges_analysis` (`{genome}.{final_loci,homology_loci,ltr_structure,reduction_multiplicity,counts,provirus_overlap,ltr_interaction,probe_domain_overlap,reduction_coverage}.csv`), `overlap_matrix`, `segmented_species`, `probe_pairs`, `solo_ltr`, `hotspots`, `probe_dict`, `full_genome_blast`, `taxonomy_classification`.
- `data/tables/<name>/` - the pipeline-internal **Parquet** copy of each of those table groups, mirroring the `results/tables/` layout. `data/tables/_input/` holds the user-provided probe CSV.
- `results/manifest/` - per-genome run manifest YAMLs: provenance only (generator build, timestamp, input md5s, resolved parameters, seed).
- `results/plots/` is laid out to mirror the pipeline stages (so the folder tree *is* documentation). Each stage writes one multi-page PDF (one per genome where the pages are per genome), opening with a key page; every figure follows one visual system, see [visual_style.md](visual_style.md):
  - `plots/ranges/` - the **ranges stage** (pre-classification): `homology/homology.pdf` (from `plot2sort`: density, raincloud, query-coverage, bar, **virus-by-species stacked bar**, balloon, heatmap-probexspecies, virus waffle, three alluvia, for the main and the accessory probe sets) and `integration/integration.pdf` (from `stage_plot_generator`: homology<->LTR concordance, structure, refinement funnel, multiplicity, **pre-reduction overlap/redundancy** - self-overlap degree, reciprocal-overlap fraction, reduction fold, total-bp before/after - and **LTRharvest/LTRdigest interaction** - distance-to-nearest-retrotransposon, position-within-element metagene, probexPfam-domain overlap, per-feature breakdown, strand concordance, element length vs hits). Every integration page names its range tier in the subtitle.
  - `plots/classification/` - the **taxonomy stage**: `taxonomy/taxonomy.pdf` (below), `structure/structure.pdf` (from `erv_like_plot_generator`: structural class, completeness, main-gene count, gene combinations, gene order, length, lineage by gene), `loss/loss.pdf` (below), `segments/by_<rank>/` (one PDF per segment plus `overview.pdf`) and `solo_ltr/` (one PDF per genome plus `all_species.solo_ltr.pdf`).
  - `plots/circle/` (per-genome Circos-style PNG + PDF; the stage is currently broken and not yet in the house style) and `plots/hotspot/` (one PDF per genome) sit alongside.
- **Taxonomic classification** - `data/taxonomy_reference/` holds the build-once reference (`retro_reference.{faa,csv}`, `taxonomy.tsv`, `erv_class.tsv`, `trees/`, `manifest.yaml`); gitignored, rebuilt via `make reference`. Per-genome outputs: `results/tables/taxonomy_classification/{genome}.loci.csv` (+ Parquet under `data/tables/`) - the per-locus taxon-founded ERV assembly (`taxon_call`, `rank`, `confidence`, `confidence_tag`, `n_blastx_hits`, `method`, `is_mosaic`, `mosaic_composition`, `erv_class`, `completeness`, `canonical_order`, `structure_class`, `domain_tier`, `oversized`, per-gene calls, `probe_label_set` provenance, `source`); `{genome}.orphans.csv` - the recovered, proximity-clustered orphan tier (same schema, `source=orphan`, gated to classified-only); `{genome}.classification_counts.csv` + `{genome}.orphans_counts.csv` - blastx-stage loss counters (incl. `structure_*` / `loci_domain_*` tallies + `orphans_total`/`orphans_recovered`); `results/tables/taxonomy_classification/classification_report.csv` - tidy counts by taxon / confidence / method + mosaic + integration totals, split by tier; **`catalog.csv`** - the unified authoritative catalog: LTR-flanked proviruses  U  clustered orphan loci as one fully non-overlapping record set (LTR-flanked-precedence), `source` keeping the confidence gradient (ADR-010); `results/tracks/taxonomy/{genome}.gff3` + `.bed` (IGV, colour-by-taxon; GFF3 attrs carry `structure_class` + `domain_tier`); `results/plots/classification/taxonomy/taxonomy.pdf` - a key page and 23 pages: lineage composition per host, per host over both tiers and per tier, rank resolution, method mix, ERV-class composition, tier yield, structural class, completeness by tier, domain support, confidence in four views (share, counts, a 0.05-step gradient, calibration by method), blastx evidence depth, confidence against evidence, the two **lineage trees** (confidence and tier by viral lineage, ordered by the reference taxonomy; an explanatory placeholder when no tree is available) and a **mosaic/recombination sub-panel** (mosaic burden, lineages inside mosaic loci, the gene-to-lineage alluvium, recombination-partner heatmap, per-gene discordance), derived from the loci + orphan tables so they stay concordant. Hosts are rows in the host-tree order, with the tree beside them. Tree coordinates live in `results/tables/taxonomy_classification/trees/`. Per-segment deliverables are split by TYPE: the tables in `results/tables/taxonomy_classification/segments/by_<rank>/` with a top-level `segment_summary.csv`, and the figures in `results/plots/classification/segments/by_<rank>/`: one PDF per segment (the `plots.segment_panel` subset of the taxonomy and structure pages) and `overview.pdf`. **Loss analysis** - `results/tables/loss_analysis/loss_analysis.csv` (per-genome per-stage attrition funnel) + `novel_candidates/{genome}.novel_candidates.csv` (loci with `n_blastx_hits == 0`) + `results/plots/classification/loss/loss.pdf` (a key page, then the per-genome funnel, the main-chain waterfall, the step-retention heatmap, orphan recovery and the novel-candidate burden).
- `results/tables/hotspots/` + `results/tracks/hotspots/` - per-window CSV/Parquet + provenance manifest, per-region `{genome}.hotspots.csv`, merged-region GFF3/BED, and `results/plots/hotspot/{genome}.hotspots.pdf` (Manhattan and Q-Q pages per tested label, karyotype, summary, composition). Detection is a deterministic Negative-Binomial GLM (`hotspot_detector.R` + `hotspot/*`). **ADR-012**: it counts one row per integration EVENT from the authoritative per-locus `catalog.csv` (`hotspot.input: catalog`; the old `valid` tier is retired because it multi-counted a multi-gene provirus once per gene), groups by the calibrated `segment` / `taxon_call` instead of the legacy probe `label`, picks the tier with `hotspot.source` (`ltr-flanked` default), and annotates every called region with its structural composition (`n_full` / `n_partial` / `n_gene`), tier split, dominant taxon and mean confidence. Counting events rather than hits is several times sparser, so expect fewer calls; `source: both`, a larger `window_size` or `input: original` recover density. The NB / masking / windowing statistics are unchanged. See [configuration.md `## hotspot`](configuration.md) and [ADR-012](adr/ADR-012-hotspot-on-the-assembled-catalog.md).
- `data/ltr_scn/` - LTRharvest screen-format intermediate, `{genome}.scn`. Its only consumer was the archived LTR_retriever route (ADR-017); `ltr_harvester` still declares it as an output, because removing an output from that rule would change its signature and re-fire a many-hour stage for no gain.

## Key configuration

All user-tunable parameters live in [`data/config/config.yaml`](../data/config/config.yaml); validation rules are in [`data/config/schema.yaml`](../data/config/schema.yaml). See [`docs/usage.md`](usage.md) for field-by-field reference.

Decisions captured under [`docs/adr/`](adr/):
- ADR-001: single conda/mamba env vs per-rule `--use-conda`.
- ADR-002: configurable metadata aggregation strategies across merged ranges.
- ADR-014: publish the EPA-ng placement evidence out of scratch; heat-trees and EDPL per genome; co-phylogeny of host genomes from ERV placement, compared to the host tree by bipartition.
- ADR-003: retroviral-only pre-filter for LTR_retriever (Coupling A).
- ADR-004: `SPECIES_POST` -> Snakemake checkpoint + runtime `species_with_hits(wildcards)` resolver.
- ADR-006: canonicalise genome FASTA filenames to `.fa` via symlink (handles `.fna`/`.fasta`/`.ffn` inputs) - owned by `genome_fasta_normalizer_setup`.

## Design principles

- **Reproducibility**: single pinned env; deterministic rules where possible; stochastic steps (hotspot permutations, Entrez fetches) documented.
- **Resilience**: Snakemake checkpointing; retry logic on Entrez; validator checks tool versions before run.
- **Modularity**: one script per responsibility; strict separation of Python (I/O, orchestration) and R (analysis, plotting).
- **Elegance**: SOLID + DRY; GenomicRanges-first interval ops in R; pathlib-first path handling in Python.
